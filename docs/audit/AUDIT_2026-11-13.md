# Audit and remediation — 2026-11-13

Scope: the whole repository at `d6a59eb` (code, build, CI, tests, docs), on the
Raspberry Pi 4 (`darkcrystal`, kernel 7.0 raspi, GCC 15.2, 800x480 DSI panel).
The prior audit (`TECHNICAL_DEBT_2026-11-11.md`) and its fixes
(`P0_REMEDIATION.md`) were re-verified first; every prior fix in scope held.

Evidence for this document is under `tests/evidence-audit-20261113/`
(generated, not committed). The Pi's clock runs about three days slow, so
timestamps inside the evidence say 2026-11-10.

## Verification method

Every fix has a regression check, and every check was **mutation-tested**: the
original defect was re-introduced on the Pi and the check had to fail. Display
behaviour is verified from outside the rendering process by
`tests/scanout_probe`, which samples the CRTC's scanned-out framebuffer id and
pixels. Rendered output was also inspected visually from frame captures.

| Area | Check | Mutants re-introduced | Caught |
|---|---|---|---|
| Core/IPC | `tests/test_p0.c` (+86 checks), `tests/test_cli.py` | 14 | 14 |
| Display presentation | `make present-hardware` | 5 (incl. "no page flip") | 5 |
| GLES backend | `tests/test_gles_state.c` | 5 | 5 |
| Text rendering | `tests/test_text_render.c` | 1 | 1 |
| evdev input | `tests/test_evdev.c` | 5 | 5 |
| NEON fallback | `make check-scalar` + new `m4_transpose` test | 1 | 1 |

One mutant (removing the in-call vsync wait while keeping page flips) survived
and is behaviourally equivalent: the flip is retired by the next present.

## Findings and fixes

### Display (highest impact)

- **No page flips after the first frame.** Baseline probe of the old code:
  1 framebuffer change for 6 rendered colours; the panel showed 3 of them, each
  drawn into the buffer being scanned out. Now each present flips its own
  buffer: with vsync, 240/240 frames observed as hardware flips at 60.0 FPS,
  exact colour order, never rendering into the scanned-out buffer.
- **Rendering is uncapped by default** (maintainer decision): present never
  waits for the display, so frame rates measure system capability. Frames the
  panel cannot show are dropped rather than torn (5 shown, 235 dropped in
  80 ms, matching vblanks). Render rates match the pre-fix figures:
  `test_06_raycast` 446 FPS, `test_08_raycast_orbit` 110 FPS. `vsync = true`
  remains available to pace to the display.
- Takeover with no active CRTC now uses `possible_crtcs` (verified with the
  CRTC disabled beforehand); a mode/surface size mismatch is refused cleanly;
  `AddFB`/`SetCrtc` results are checked; failed init releases its fd, GBM/EGL
  objects and DRM master (verified: no leaked fd, later init succeeds).
- Shutdown: the implicit console handback measured in `GLES_SHUTDOWN_PLAN.md`
  is kept (verified: fbcon framebuffer back on screen after every run). The
  code comment claiming an explicit handback was corrected.

### Core and IPC

- Zero channel budget wedged a channel (on RT, all IPC): rejected.
- MPMC submit ring spun forever at the u32 wrap: modular `int32_t` difference.
- Malformed messages ACKed as success: schema gate in every node,
  `HS_ACK_INVALID`; input opcodes given schema entries (previously every input
  message failed validation). Later moved to a single check at routing (see
  "Validation at routing" below).
- Late IPC result answered the next request: server-assigned correlation ids.
- `accept()` errors ended the IPC thread: transient errors retried (verified
  with real `EMFILE`).
- Implicit wildcard TCP bind; socket mode window; `/tmp` client default with no
  peer check: loopback default, 0600 before bind, per-user default path and
  `SO_PEERCRED` (verified against a socket owned by `nobody`).
- `CLOCK_REALTIME` timed waits: `CLOCK_MONOTONIC` condvars.
- Payload ring written from producer threads: inline payload sends.
- Strict CLI parsing; server-mode errors explained; `neogpu_tool --help`.

### Backend, text, math, input, tools

- Backend: per-bank vertex counts, real instanced draws with per-instance
  offsets, `OP_DRAW_TEXT` text instead of a full-screen checker, scissor trim,
  per-backend context, shader leak, pre-present capture API.
- Text: glyph UVs were flipped (fragments on screen) and digits/entities were
  loaded at the wrong codes (blank scores). Rendered glyphs now match the atlas
  cell-for-cell (0/297 mismatches; old mapping 130).
- `m4_transpose` swapped rows 1 and 2 (no caller yet). The portable NEON
  fallback never compiled and was never included; it is now used for non-ARM
  builds and tested on ARM with `-DHS_NEON_SCALAR` (142/142).
- evdev: `SYN_DROPPED` resync, framing events off the queue, unplug without
  hotplug releases keys (even with a full queue) and frees the slot.
- Storage name truncation/aliasing and short-file loads; font atlas bounds.
- Demos: procgame SIGFPE at score 1100; pong_ai rendered nothing (now fully
  message-driven, verified by frame capture and 150 observed flips); capture
  demos now replay the file they read back; screenshots read before presenting
  and with `GL_RGBA` (GL_RGB reads failed silently); no `/tmp` outputs; pong
  raw terminal input with real arrow keys.

### Build, CI, docs

- `make check-sources` failed (`tests/panel_mode_probe.c`), so CI never reached
  its sanitizer/race stages. Fixed; `check-sources` no longer litters `a-*.d`.
- CI adds `check-scalar` and the legacy benchmark build.
- `src/benchmark.c` now builds (`make bench-legacy`); its math loop was
  dead-code-eliminated (0.00 ms) and compared unequal work. It now measures
  equal dependent work: NEON 0.53 ms vs auto-vectorised scalar 0.45 ms per
  100k multiplies. That is reported as measured, not as a NEON win.
- Docs corrected: README (display rate, demos, IPC, layout, targets),
  CHANGELOG (one Unreleased section, missing commits, ML-era entries removed),
  CAPTURE_FORMAT (version 1), IPC_CONTROL, MESSAGE_ABI, INPUT_STREAM, AGENTS.
  `.github/README.md` (a stale copy GitHub showed instead of the README)
  removed. Foreign `.gitignore` entries removed without exposing any file.

## Performance against the pre-audit code

`tests/test_reference_refresh.py` was run on `d6a59eb` (before; the failing
`check-sources` stage omitted), on the remediation (`23ae2a8`) and after the
follow-up fixes (`3434853`). Evidence: `tests/evidence-reference-*`.

| Measure | Before | Remediation | Now |
|---|---|---|---|
| Executor frame total vs direct GLES (us) | 465.5 / 463.6 | 479.8 / 464.3 | 467.6 / 460.6 |
| Executor submit (us) | 78.8 | 88.1 | 79.0 |
| Lifecycle submit, alternate / same / mixed (us) | 399.6 / 223.9 / 280.1 | 471.1 / 258.7 / 304.4 | 396.9 / 218.1 / 277.2 |
| Legacy scenes/s, 1 / 64 draws (M) | 1.073 / 0.130 | 0.991 / 0.123 | 1.087 / 0.126 |
| Raycast FPS, test_06 / test_08 (3 alternating runs) | 446 / 110 | 446 / 110 | 446 / 110 |

Causes, found by profiling and A/B builds rather than assumed:

- Legacy path: the node schema gate (`hs_validate_message` per message).
  Removing the gate entirely restored the old rate, confirming the cause. The
  inline `hs_message_conforms()` costs about 17 instructions per message; it
  remains about 3% at 64 draws per scene.
- Executor and lifecycle: the plain-draw shader read a third (constant)
  attribute, re-emitted on every draw that rebinds its buffer, and
  `eglSwapInterval(0)` was called on every present. The remaining ~7 us per
  frame is the page flip, which the old code never did.
- Transport rows are unchanged: the transport binary is byte-identical in
  every run; its 8-producer 64-draw row varied 1.007 to 1.100 between runs.

## Validation at routing (`bf8bfa3`)

The remaining legacy-path cost was the schema check in every node. Messages
are now checked once, when the step thread routes them, and refused before
any node, render recording or capture sees them. Messages the runtime builds
itself (`hs_gpu_*` helpers, node acks) are sent with `hs_send_trusted()` and
skip the check; the mark lives in the queue slot, is rewritten on every
enqueue and cannot be set through `Message`. Everything external (`hs_send`,
`hs_try_send`, IPC, replay) is still checked, and sanitizer builds abort if a
trusted message fails the check. The blocking send's backpressure loop also
moved out of line, so a normal send is one enqueue attempt. Behaviour is in
`docs/interface/MESSAGE_ABI.md` (Validation).

Found by the new tests: `hs_gpu_stencil` and `hs_gpu_stencil_func` sent 8
bytes for a 4-byte schema, so since the node check they were always refused
and stencil state never applied; the system node printed `OP_TRACE`/`OP_ERROR`
strings without any check.

Verification: a 20,000-message fuzz through every public send call (no
non-conforming message reaches a node), every `hs_gpu_*` helper with
`validate_on_send` off and on, queue-slot reuse in both directions, replay of
a malformed capture, and the sanitizer abort. All 16 reintroduced defects
were caught. Evidence: `tests/evidence-ingress-20261114`.

Reference harness on `bf8bfa3` (all 18 stages passed;
`tests/evidence-reference-bf8bfa3-candidate`), against `3434853`. Frame rates
are given as a ratio to the frozen `7d1889d` build measured in the same run,
because that build itself moved by up to 5% between runs:

| Measure | Before (`d6a59eb`) | `3434853` | `bf8bfa3` |
|---|---|---|---|
| Legacy, 1 draw (rate / frozen) | 0.961 | 0.973 | 0.975 |
| Legacy, 64 draws (rate / frozen) | 0.999 | 0.975 | 1.032 |
| Lifecycle submit, alternate / same / mixed (us) | 399.6 / 223.9 / 280.1 | 396.9 / 218.1 / 277.2 | 389.3 / 211.8 / 269.0 |
| Microbenchmark, 1 thread (M msg/s) | 6.02 | 11.86 | 13.59 |

Lifecycle submit time is lower in all seven scenes; executor frame totals,
transport and native/reference frame rows are within run-to-run variation.
Per-message counters on the legacy benchmark (`perf stat`): 64 draws
216.5 -> 205.0 cycles (pre-audit 210.8); 1 draw 567.1 -> 544.8 (549.2). Most
of the saving is the send fast path; moving the check is worth about 1.7% of
cycles at 64 draws. An earlier version with the trusted flag at the end of
the slot was 3-5% slower, and carrying it in `Message` padding was no better;
both were dropped.

## Idle work on the message path (`d71485b`, `a184dbb`)

Profiling the legacy path after the routing change found work done for
nothing:

- `hs_step` called every node's `process_fn` on every step, inboxes empty or
  not. A node has no idle work, so it now runs only when its inbox has
  messages.
- `hs_gpu_process` stepped until a step made no progress, so every frame paid
  for one full step that polled empty queues. `hs_step` now records in
  `HSSystem.step_pending` whether it left work behind (a channel at its
  budget, or a message sent during the step waiting in an inbox), and
  `hs_gpu_process` stops when nothing is left. With participants attached it
  keeps the old loop.
- Render commands were built on the stack and copied into the list; they are
  now validated, then written in place.
- With cheaper steps the step thread kept pace with a spinning producer, and
  the producer's read of the step thread's `head` on every send then cost a
  cache miss per message: the 1-thread microbenchmark fell 14.24 -> 12.50 M
  msg/s in A/B runs. The producer now caches `head` on its own line and
  re-reads it only when the lane looks full, as the reference SPSC queue does.

Verification: new `test_p0` cases (no node runs on an empty step; acks and
messages sent back to an earlier node are applied within one
`hs_gpu_process`; a budget-limited channel drains in one call; commands are
written whole; `OP_FRAME_BEGIN` resets the list; a full list is flagged only
by render commands; drained lanes are reused without spilling, an undrained
one never overwrites). Mutants: 11 of 12 caught; the survivor (not resetting
the cached head in `hs_clear`) is equivalent, since a stale cache only forces
a re-read or understates free space. Evidence: `tests/evidence-msgpath-20261114`.

| Measure | `bf8bfa3` | `a184dbb` |
|---|---|---|
| Legacy cycles/msg, 1 / 64 draws (`perf stat`) | 549.4 / 203.2 | 364.6 / 169.0 |
| Legacy M scenes/s, 1 / 64 draws (7 alternating rounds) | 1.080 / 0.134 | 1.623 / 0.161 |
| Legacy rate / frozen `7d1889d`, 1 / 64 draws (harness) | 0.975 / 1.032 | 1.484 / 1.215 |
| Microbenchmark 1 / 2 / 4 / 8 threads (M msg/s, harness) | 13.59 / 7.17 / 7.35 / 7.95 | 15.83 / 7.04 / 7.17 / 8.34 |

The reference harness passed all 18 stages
(`tests/evidence-reference-a184dbb-candidate`). Transport, executor,
lifecycle and native/reference frame rows are within the variation seen
between earlier runs.

## Retained limitations (explicit)

- Input aggregate state is last-event-wins across devices; removal of one
  device releases keys held on others.
- `OP_CLEAR`/`OP_CLEAR_DS` honour clip and write masks (GL semantics, now
  documented) rather than always clearing the whole target.
- `OP_DRAW_TEXT` has no position or colour in its ABI: white, stacked lines.
- The payload ring can still be overwritten if more than 4096 payload-bearing
  messages are pending at once within the step thread; producer threads no
  longer allocate from it.
- IPC remains trusted-local tooling without authentication.
- 6.4 GB of historical `tests/evidence-*` collections remain on the Pi
  (untracked); 14 docs cite 87 of those paths, so they are not reproducible
  from a clone. Pruning is the maintainer's decision.
- The Pi's clock is ~3 days slow (no RTC; NTP not syncing), which skews commit
  dates.
