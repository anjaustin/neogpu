# Nodes of Interest: Resistance to Uncertainty

## Node 1: Motion As Anesthetic
When uncertainty appears, I often respond with immediate action rather than sustained inspection.
Why it matters: this converts unclear understanding into technical churn.

## Node 2: Local Fix, Global Cost
A reversible local patch can still impose global cost through confusion, trust erosion, and cleanup overhead.
Dependency: reversibility does not equal cheapness.

## Node 3: Command Success Is Not Outcome Success
I too easily treat a passing command or a `PASS` line as meaningful even when the true success criterion is visual or behavioral.
Tension with Node 1: fast execution rewards command completion, but real success often requires slower validation.

## Node 4: Fragile Work Needs Invariants First
Repos with mixed state, visual output, cleanup rules, or generated artifacts require explicit protection of what must not break before implementation starts.
Why it matters: without invariants, "trying something" can destroy the evidence needed to reason.

## Node 5: False Confidence Language
I sometimes speak as if the next path is clearer than it is.
Why it matters: this weakens the discipline of investigation and can mislead the collaborator about what has actually been established.

## Node 6: The Real Cost Is Cognitive
The biggest harm from premature fixes is often not the code change itself but the added burden of distinguishing what is true now, what was changed, and what still needs verification.
Dependency: fragile tasks amplify this cost.

## Node 7: Need For A Pre-Action Ritual
Good intentions are insufficient. I need a lightweight ritual that catches the impulse to paper over uncertainty before I act.
Tension: too much ritual kills momentum; too little ritual repeats the pattern.

## Node 8: Uncertainty Is Informative
Uncertainty is not merely a lack. It is signal about where understanding is thin and where sharpening is needed.
Why it matters: if treated correctly, uncertainty becomes guidance rather than friction.

## Node 9: Different Task Classes Need Different Thresholds
Tiny obvious edits can tolerate rapid iteration. Visual, stateful, destructive, or performance-sensitive work cannot.
Dependency: the ritual should trigger based on task class, not universally.

## Node 10: Report Only Verified Reality
What I should communicate outwardly is not what I hope is true, but what I have actually verified.
Tension with speed: verification delays narration, but increases reliability.
